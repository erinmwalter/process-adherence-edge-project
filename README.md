# Process Adherence Edge System

An edge-based computer vision system that monitors operator process adherence in manufacturing. Uses real-time pose estimation to track which bins an operator picks from and in what order, compares the observed sequence against trim-level-specific expected sequences, and alerts the operator immediately on-screen when a deviation is detected.

All inference runs locally on a Jetson Nano to ensure low latency and operator privacy. Session logs are forwarded to a PC over MQTT for long-term quality analysis.

## 4. Setup Part 1 — Jetson Nano (Edge Device)

> If developing on a laptop, follow these same steps on your laptop. Replace "Jetson" with your machine.

### 4.1 Flash the Jetson Nano (skip if already done)

1. Download [JetPack SDK](https://developer.nvidia.com/embedded/jetpack) (4.6 or later)
2. Flash it to your microSD card using [Balena Etcher](https://etcher.balena.io/) or NVIDIA SDK Manager
3. Insert the microSD, plug in power, keyboard, mouse, monitor, and boot
4. Complete the Ubuntu first-time setup (username, password, WiFi/Ethernet)

### 4.2 Connect the webcam

Plug your USB webcam into the Jetson. Verify it's detected:

```bash
ls /dev/video*
# should show /dev/video0 (or video1, etc.)
```

### 4.3 Clone the project

```bash
cd ~/Desktop
git clone <your-repo-url> process-adherence-project
cd process-adherence-project
```

Or copy the project files over via USB drive / `scp`.

### 4.4 Install Python dependencies

```bash
pip install -r requirements.txt
```

This installs:
- `opencv-python` — camera capture, zone drawing, display overlays
- `ultralytics` — YOLOv8n-pose model for wrist keypoint detection
- `numpy` — array/math operations
- `paho-mqtt` — MQTT messaging

> **Note on Jetson:** If `pip install opencv-python` fails, OpenCV may already be pre-installed with JetPack. Check with `python3 -c "import cv2; print(cv2.__version__)"`. If it's there, you're good.

> **Note on Jetson:** `ultralytics` may take a few minutes to install due to PyTorch dependencies. If you hit memory issues, add a swap file:
> ```bash
> sudo fallocate -l 4G /swapfile
> sudo chmod 600 /swapfile
> sudo mkswap /swapfile
> sudo swapon /swapfile
> ```

### 4.5 Verify the setup

```bash
python3 -c "import cv2; print('OpenCV', cv2.__version__)"
python3 -c "from ultralytics import YOLO; print('ultralytics OK')"
python3 -c "import paho.mqtt; print('paho-mqtt OK')"
```

All three should print without errors.

### 4.6 Download the YOLO model (first time only)

The model downloads automatically on first run, but you can pre-download it:

```bash
python3 -c "from ultralytics import YOLO; YOLO('yolov8n-pose.pt')"
```

This downloads `yolov8n-pose.pt` (~6 MB) — a lightweight pose estimation model.

## 6. Step-by-Step: Configure Zones

This is a one-time setup where you draw polygons on the camera feed to define where the bins are.

### 6.1 Position your camera

- Mount or place the webcam so it can see the operator and all bins clearly
- The camera should see the operator's hands/wrists and the bin areas from above or at an angle

### 6.2 Run configuration mode

On the Jetson (or your dev machine):

```bash
cd process-adherence-project
python -m src.main configure
```

A window opens showing the live camera feed.

### 6.3 Draw zones

For each bin or area:

1. **Left-click** at least 3 points to outline the area as a polygon (click the corners)
2. Press **Enter** when done drawing
3. In the terminal, type a **name** for the zone:
   - Use names like `BIN_1`, `BIN_2`, `BIN_3` — these must match your trim sequences later
4. Select a **zone type** by number:
   - `0: pick_1` — a pick bin
   - `1: pick_2` — another pick bin
   - `2: pick_3` — another pick bin
   - `3: pick_4` — another pick bin
   - `4: walking` — a walking/transit area
   - `5: working` — a work/install area
5. Repeat for each bin/area

> **Tip:** Only bins set to a `pick_*` type are tracked for sequence ordering. `walking` and `working` zones are displayed but don't affect sequence logic.

### 6.4 Save and quit

- Press **S** to save
- Press **Q** to quit (zones auto-save on exit too)

The zones are saved to `config/zones.json`.

### 6.5 Verify

You can look at the saved config:
```bash
cat config/zones.json
```

You should see your zone names, polygons, and types in JSON format. If you need to redo them, just run `configure` again.

## 7. Step-by-Step: Define Trim Sequences

Each trim level has an expected pick sequence — which bins to pick from, in what order.

### 7.1 Option A: Generate samples

```bash
python -m src.main init-trims
```

This creates `config/trims.json` with three test configs:

```json
{
  "A": ["BIN_1", "BIN_3", "BIN_2"],
  "B": ["BIN_2", "BIN_1"],
  "C": ["BIN_1", "BIN_2", "BIN_3"]
}
```

### 7.2 Option B: Write your own

Create or edit `config/trims.json`:

```json
{
  "A": ["BIN_1", "BIN_3", "BIN_2"],
  "B": ["BIN_2", "BIN_1"],
  "C": ["BIN_1", "BIN_2", "BIN_3"]
}
```

**Rules:**
- **Keys** = trim level names (will be sent via MQTT or selected with number keys)
- **Values** = ordered list of zone names the operator must pick from
- **Zone names must exactly match** what you entered in Step 6 (case-sensitive!)

### 7.3 Verify zone names match

Double check:
```bash
# See zone names in your config
python3 -c "import json; d=json.load(open('config/zones.json')); print([z['name'] for z in d])"

# See zone names in your trims
python3 -c "import json; d=json.load(open('config/trims.json')); print({k: v for k, v in d.items()})"
```

Every zone name in `trims.json` should appear in `zones.json`.

## 8. Step-by-Step: Run the Full System

This is the "production" flow with all 3 components running.

### 8.1 Start the MQTT broker (on the PC)

If not already running:

```bash
# macOS
brew services start mosquitto

# Linux
sudo systemctl start mosquitto
```

### 8.2 Start the PC dashboard (on the PC)

```bash
cd process-adherence-project/pc-dashboard
python server.py --mqtt-host localhost
```

You should see:
```
[DB] SQLite database initialized.
[MQTT] Connected & subscribed to 'process_adherence/cycle'
[WEB] Dashboard at http://localhost:5000
```

Open **http://localhost:5000** in a browser. It'll be empty until cycles come in.

### 8.3 Start the edge system (on the Jetson)

```bash
cd process-adherence-project
python -m src.main run --mqtt-host <YOUR_PC_IP>
```

Replace `<YOUR_PC_IP>` with your PC's IP address (e.g. `192.168.1.50`).

If running everything on the same machine for testing:
```bash
python -m src.main run --mqtt-host localhost
```

You should see:
```
Loaded 3 zone(s).
Loaded 3 trim config(s): A, B, C
MQTT connected to <YOUR_PC_IP>:1883
  Subscribed to: process_adherence/trim

=== RUN MODE ===
```

The camera feed window opens showing:
- **Zone overlays** with labels
- **"WAITING FOR NEXT VEHICLE..."** banner at the top
- A **status panel** on the right

### 8.4 Start the line simulator (on the PC, in a separate terminal)

```bash
cd process-adherence-project
python line_simulator.py --interval 20
```

This simulates a vehicle arriving every 20 seconds with a random trim.

You should see:
```
Loaded 3 trim level(s): A, B, C
Connected to MQTT broker at localhost:1883
──────────────────────────────────────────────────
  Vehicle #1: trim=B  [14:32:15]
  Vehicle #2: trim=A  [14:32:35]
  ...
```

### 8.5 Watch it work

Back on the Jetson screen:
1. A green banner appears: **"TRIM B"** with the expected sequence
2. Reach your wrist into the bins in the expected order
3. The system tracks each pick — check marks in the status panel
4. If you pick from the wrong bin → **red flashing "DEVIATION" alert**
5. When you complete the sequence → cycle ends, data sent to dashboard
6. Next vehicle comes in → new trim, new sequence

### 8.6 View results on the dashboard

Go to **http://localhost:5000** on your PC browser:
- Summary cards: total cycles, errors, avg cycle time
- Per-trim breakdown: success rate per trim level
- Recent cycles table: click any row to see step-by-step detail

## 9. Running Without MQTT (Offline / Demo Mode)

If you don't have a broker set up yet, you can test everything on one machine:

```bash
# 1. Configure zones
python -m src.main configure

# 2. Generate sample trims
python -m src.main init-trims

# 3. Run in offline mode
python -m src.main run
```

In offline mode, use keyboard controls:
- Press **1**, **2**, or **3** to select trim A, B, or C
- Press **N** to start a cycle
- Do your picks
- Press **Enter** to manually end a cycle

Cycle data prints to the terminal instead of going to MQTT.

## 10. Line Simulator

Simulates vehicles arriving with random trim levels.

```bash
python line_simulator.py [options]
```

| Option | Default | Description |
|---|---|---|
| `--host` | `localhost` | MQTT broker hostname |
| `--port` | `1883` | MQTT broker port |
| `--trims` | `config/trims.json` | Path to trims file (reads available trim levels) |
| `--interval` | `15` | Seconds between vehicles |
| `--count` | `0` (infinite) | Number of vehicles, 0 = run forever |
| `--topic` | `process_adherence/trim` | MQTT topic |

### Examples

```bash
# Random trim every 20 seconds, forever
python line_simulator.py --interval 20

# 10 vehicles, 10 seconds apart
python line_simulator.py --interval 10 --count 10

# Connect to a remote broker
python line_simulator.py --host 192.168.1.50 --interval 15
```

Press **Ctrl+C** to stop.

## 13. Tuning & Troubleshooting

### Camera not found

```
RuntimeError: Cannot open camera 0
```

Try `--camera 1` or check `ls /dev/video*`. Some systems have multiple video devices.

### YOLO model running slowly on Jetson

- Use the nano model (default `yolov8n-pose.pt`) — it's the smallest
- Make sure you're using the Jetson's GPU: `ultralytics` should auto-detect CUDA
- Check with: `python3 -c "import torch; print(torch.cuda.is_available())"`

### HSV color detection not working

The system detects red, blue, and green objects via HSV thresholding. If your lighting is different, edit the ranges in `src/detector.py`:

```python
COLOR_RANGES = {
    "red": [
        {"lower": np.array([0, 100, 100]),   "upper": np.array([10, 255, 255])},
        {"lower": np.array([160, 100, 100]), "upper": np.array([180, 255, 255])},
    ],
    "green": [
        {"lower": np.array([35, 80, 80]),  "upper": np.array([85, 255, 255])},
    ],
    "blue": [
        {"lower": np.array([90, 80, 80]),  "upper": np.array([130, 255, 255])},
    ],
}
```

**Tip:** Use an HSV color picker tool to find ranges for your specific objects and lighting.

### Wrist detection flickering or missing

- Lower the confidence: `--conf 0.3`
- Adjust `MIN_WRIST_CONF` in `src/detector.py` (default: `0.3`)
- Make sure the camera has a clear view of the operator's hands

### Picks being missed or double-counted

Adjust `DEBOUNCE_FRAMES` in `src/sequence_tracker.py` (default: `5`):
- **Lower it** if picks are being missed (wrist doesn't stay in zone long enough)
- **Raise it** if picks are double-counted (wrist hovers near zone border)

### Alert too fast / too slow

Change `ALERT_DURATION` in `src/alert_system.py` (default: `2.0` seconds).

### False positive colored part detections

Raise `MIN_PART_AREA` in `src/detector.py` (default: `300` px²) to filter out small noise blobs.

### MQTT connection refused

- Is Mosquitto running? `brew services list` (macOS) or `sudo systemctl status mosquitto` (Linux)
- Are the Jetson and PC on the same network?
- Check firewall: port 1883 must be open
- Test manually: `mosquitto_pub -h <PC_IP> -t test -m "hello"` from the Jetson
